A third failure shape · cheap attempts, costly failures

Which denominator are you paying for?

A fictional service completes every attempt, but its first configuration misses authorization on three of four attempts. The repaired configuration costs more per attempt. Counting all costs against jointly passing attempts reverses the apparent cost advantage.

Build a dossier from your own evidence · Use independently pinned inputs in CI

Why these views?

FinOps unit economics motivates making the denominator explicit; Google SRE monitoring guidance explains why latency percentiles reveal information averages hide. These sources inform the questions, not validation of this synthetic fixture or its thresholds.

Inspect it. Download it. Recompute it.

  1. Read either review in your browser. Expand the scenario details to see what changed.
  2. Download its pack and extract every file into one folder (six for the policy-only examples; eleven for diagnostic dossiers).
  3. From a checkout of this repository, install the current harness and verify that folder:
python -m pip install -e harness
aau evaluation-pack verify /path/to/extracted-pack

Candidate A exits 0. Candidate B exits 1: its pack verifies, but its constraints are not met. Exit 2 indicates an invalid, incomplete, modified, or incompatible pack. Failure evidence is a useful result, not a broken download.

Verification recomputes the review, HTML, and byte manifest from the included policy and evaluations. Keep the matching harness revision: changes to the renderer or scoring logic can make an older pack incompatible.
