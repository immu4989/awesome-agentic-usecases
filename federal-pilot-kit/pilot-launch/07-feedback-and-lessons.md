# 07 — Feedback and reusable lessons

Collect feedback through an agency-approved channel. Public issues may contain only public or
synthetic information and must not identify a person, proposal, source-selection participant,
security weakness under embargo, controlled record, or vendor-confidential fact.

## Feedback record

| Field | Entry |
|---|---|
| Role perspective—not personal identity | _Operator, affected user, reviewer, responder, control owner_ |
| Workflow moment | _What was the person trying to do?_ |
| Expected result | _Observable and testable_ |
| Observed result | _Include stable evidence reference_ |
| Consequence | _Mission, time, cost, safety, rights, accessibility, trust_ |
| Workaround or intervention | _What happened next?_ |
| Proposed requirement/test change | _Exact and reviewable_ |
| Disclosure classification and owner | _Required before sharing_ |

## Lesson record

Write one lesson as:

```text
Context → Requirement → Test → Evidence → Result → Lesson → Reuse conditions
```

Include what failed, not only what worked; the assumption that changed; whether the evidence was
independently reproduced; cost/data/portability implications; applicability limits; redactions;
approving disclosure role; and the next verification date. Never name a “winning” vendor or turn a
single pilot into an endorsement.
