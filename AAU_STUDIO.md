# AAU Studio

[Open AAU Studio](https://immu4989.github.io/awesome-agentic-usecases/#studio) to turn a
workflow description into an evidence-backed evaluation starting point.

Studio runs locally in the browser. It sends no workflow text to a server, uses no model,
sets no tracking cookie, and requires no account or API key.

## What Studio does

1. **Match** — describe the work, select an agent shape, and mark the consequences that
   matter. Studio ranks the complete catalog using explicit industry, capability, contract,
   and observed-failure evidence.
2. **Explain** — every recommendation names the signals that produced the match and shows
   proof available in the repository: committed model results, reproducible scenarios,
   observed failures, official sources, and protected human authority.
3. **Compare** — place as many as three labs beside one another without pretending unlike
   headline metrics are directly comparable. The comparison focuses on shape, contract,
   evidence, scenario volume, model artifacts, and failure patterns.
4. **Forge** — copy a zero-cost run path or download a vendor-neutral evaluation brief that
   conforms to [`docs/studio-spec.schema.json`](docs/studio-spec.schema.json), then turn it
   into a runnable adaptation with [AAU Forge](AAU_FORGE.md).
5. **Fill the gap** — when no existing lab fits, open a prefilled request containing the
   workflow, risk shape, closest verified case, and proposed verification plan.

## How matching works

The matcher is deterministic and inspectable. It rewards:

- exact or partial industry fit;
- overlap with the chosen agent shape and consequence profile;
- words shared with the catalog title, question, capabilities, contract, and observed
  taxonomy patterns; and
- verified evidence already committed for the lab.

It does not call an LLM and it does not claim semantic certainty. A score means “stronger
catalog fit under these explicit rules,” not “this is safe to deploy.” Domain owners must
still validate the rules, authority boundary, data, and consequences for a real workflow.

## Fork paths

- **Adapt the recommended lab** when the work shares its decision shape and failure trap.
- **Generate a new lab** when the workflow has distinct ground truth. The repository
  generator creates a seeded world, exact scorer, deterministic mock, tests, and result
  directories so contributors start from a passing system rather than a blank folder.
- **Request a verified use case** when a domain partner or authoritative rule source is
  needed before implementation.

The Studio evidence index is generated by `docs/make_studio_data.py` and enforced by CI.
Never edit `docs/studio-data.json` by hand.

## Compile the brief into a lab

```bash
python -m pip install -e harness[dev]
aau forge aau-evaluation-brief.json --name my-workflow-eval
```

The command generates and verifies the package, scenarios, tests, mock run, provenance manifest,
domain checklist, and standalone CI workflow. Its output is explicitly marked as an
unvalidated adaptation until qualified owners replace the generic domain rules.
